# 用户交互流程优化 - 库存确认

**Date**: 2026-02-20
**Status**: Approved

## 背景

优化用户交互流程，在计算方案前增加库存确认步骤，让用户了解现有瓦片情况并选择是否使用库存。

## 需求

1. 询问需求后，先确认库存情况再计算方案
2. 库存为空时提示用户并询问是否继续
3. 使用库存时展示两种方案供选择

## 设计

### 流程对比

| 步骤 | 当前流程 | 优化后流程 |
|------|----------|------------|
| 1 | 检查配置 | 检查配置 |
| 2 | 询问需求 | 询问需求 |
| 3 | - | **确认库存** ← 新增 |
| 4 | 计算方案 | 计算方案（展示两种） |
| 5 | 展示方案 | 展示方案 |
| 6 | 生成文件 | 生成文件 |

### Step 3: 确认库存

Agent 自动执行：
1. 检查库存文件 `scripts/inventory.json`
2. 列出可用瓦片
3. 询问用户是否使用库存

**库存为空时**：提示用户并询问是继续计算还是先入库

### Step 4: 计算方案（展示两种）

- **不使用库存**：按原有逻辑计算最优方案
- **使用库存**：展示两种方案
  1. 不考虑库存的最优方案
  2. 考虑库存的方案（显示节省多少打印）

## 决策

- **库存确认方式**：自动检查 + 用户确认
- **库存为空时**：提示并询问是否继续
- **方案展示**：展示两种方案供用户选择
