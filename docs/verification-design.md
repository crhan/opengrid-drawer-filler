# 库存感知评分系统 v2 设计文档

## 重点内容

**必须第一优先级处理，不能冲突**

- 你要做的是测试代码的实现，你要忠实的还原测试意图，而不是通过修改测试代码来让测试通过
- 你绝对不能通过调用内部函数来测试
- 这个测试文档描述的是 cli 端到端测试，你应该模拟用户的操作来重现测试场景，遵循以下步骤：
  a. 创建临时目录
  b. 生成 config 和 inventory（只做一次，后续复用）
  c. 调用 scripts/opengrid.py 脚本进行测试（多次调用）
  d. 通过脚本输出来确认测试目的达成

## 全局验证要求

所有涉及方案调整的场景（重新规划、批量优化等）都需要验证：

**格子数量一致性：** 拆分/调整前后的瓦片总格子数必须保持一致。

- 例如：原始方案 [(6,9), (6,9)] 总格子数为 6×9×2 = 108 格
- 调整后方案总格子数也必须为 108 格

## 场景 1：精确匹配

**验证意图：** 验证"有库存一定要用库存"的核心要求

**假设：**

- 抽屉：265×360（9×12格子 = 108格）
- 库存：6×9 有 2 个（6×9×2 = 108格，可完全覆盖）

**预期结果：**

- 完全使用库存，无需打印
- 打印时间 = 0

**验证目标：**

```
[ ] 打印时间 = 0
[ ] from_inventory = {'6x9': 2}
[ ] need_print = {}
[ ] 库存使用不超过提供数量
```

**验证目标：**

```
[ ] 方案包含 6x6 瓦片（使用库存）

[ ] 打印时间 < 无库存时的打印时间
```

## 无库存 Plate 边界场景

> **背景：** H2D 打印床为 300×320mm，对应 `max_cells_x = 10`，`max_cells_y = 11`（`300//28=10`，`320//28=11`）。
> 以下场景专门测试无库存时，抽屉尺寸在打印床边界附近的算法行为——核心问题是：
> **算法能否正确选择最少 Plate 的方案？换盘惩罚（60min）是否在正确边界触发？**

## 场景 9b：无库存转置维度 ⚠️ 已知缺陷

**验证意图：** 验证转置后等价的抽屉（11×10 格子）应与场景 9 产生相同结果

**假设：**

- 抽屉：308×280mm（11×10 格子，是场景 9 的宽深对调）
- 无库存
- tile(11,10) 与 tile(10,11) 物理等价，仅摆放方向不同

**关键洞察：**

- 正确行为：算法识别转置等价，输出 1 个 tile(10,11) → 1 Plate
- 当前缺陷：x=11 > max_cells_x=10，算法在分割路径中被迫生成 [(5,10), (6,10)] → 2 Plates

**预期结果（正确行为）：**

- 方案：单个 tile(10,11)
- 1 个 Stack，1 个 Plate
- 与场景 9 打印时间相同

**验证目标：**

```
[ ] plates = 1
[ ] tiles 中包含且仅包含 (10,11)
[ ] swap_penalty = 0
[ ] 打印时间 = 场景 9 打印时间
```

## 场景 10a：无库存 Y 轴偶数超出 → 仍 1 Plate

**验证意图：** 验证 Y 轴超出床限制但可均等分割时，算法选出同尺寸 tile 方案（1 Stack）

**假设：**

- 抽屉：280×336mm（10×12 格子，y=12 超出 max_cells_y=11）
- 无库存

**关键洞察：**

- y=12 均等分割为 [6,6]
- 2 个 tile(10,6) 尺寸相同 → 合并为 1 个 Stack（2 copies）→ 1 个 Plate
- 若算法选了不均等分割 [5,7]，则产生 2 个不同尺寸 → 2 Plates（次优解）

**预期结果：**

- 方案：tile(10,6) × 2
- 1 个 Stack，1 个 Plate，无换盘惩罚

**验证目标：**

```
[ ] plates = 1
[ ] unique_sizes = 1
[ ] swap_penalty = 0
[ ] tiles 全部为 (10,6)
```

## 场景 10b：无库存 Y 轴奇数超出 → 必须 2 Plates

**验证意图：** 验证 Y 轴超出且无法均等分割时，算法必然产生 2 Plates 并触发换盘惩罚

**假设：**

- 抽屉：280×364mm（10×13 格子，y=13 超出 max_cells_y=11）
- 无库存

**关键洞察：**
